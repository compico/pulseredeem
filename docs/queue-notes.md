# Заметки об очереди Яндекс Музыки

Восстановлено из удалённого MVP.md и дополнено наблюдениями с живой Яндекс Музыки.

- `position: 'last'` не подходит: трек попадает в очередь, но при «Моей волне» эта очередь не связана с очередью волны.
- `position: 'next'` — единственный рабочий способ, работает и с «Моей волной», но ненадёжно: вставка идёт после текущего индекса, поэтому два трека подряд в `next` ставятся в обратном порядке, а волна может вытеснить вставленный.
- Поэтому аддон держит одну заявку в плеере за раз, после вставки проверяет, что трек стоит **после текущего**, и при отсутствии вставляет снова (до 3 раз, не чаще раза в 1,5 с); иначе заявка отклоняется с возвратом баллов.
- id элемента очереди бывает `трек` или `трек:альбом`; сравниваем через `normalizeTrackId`.
- `addTrackToQueueById` ничего не возвращает и не сообщает об ошибке: подтверждать результат можно только по очереди.
- Вставка без активного контекста воспроизведения роняет интерфейс (`NoCurrentContextExceptions`), поэтому без текущего трека не вставляем.
- Shuffle и repeat не проверены.
- `callWithPlayer` откладывает вызовы до готовности плеера.

## Диагностика
В логе devtools при проблемах появляются записи «Вставка отложена: …» и «Трек не стоит в очереди после текущего» со срезом состояния (форма `track.id`, индекс и ближайшие id очереди).

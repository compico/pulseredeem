# Архитектура

Аддон — мост между плагином `music` в Overlay Composer и очередью PulseSync. Twitch (OAuth, награды, EventSub, статусы
погашений) целиком в OC; аддон не хранит токенов и не ходит в Twitch.

## Поток

1. `GET /plugins/music/api/next` (раз в 3 с, пока нет активной заявки). Ответ: `{item|null, resend}`.
2. `getQueueSnapshot()` → запоминаем `startIndex`; `addTrackToQueueById(trackId, {albumId, position: 'next'})`.
3. `onQueueChange`: индекс сдвинулся и `items[currentIndex].id === trackId` → `POST /started {id}`.
4. Ошибка вставки, негодная заявка или 30 минут без старта → `POST /failed {id, reason}`.

## Награда по отыгрышу и пульт

Заявка: `queued → sent → playing → played | failed`. `POST /started` переводит в `playing` (награда ещё не выполнена), `POST /played`
выполняет её, `POST /failed` отменяет (баллы возвращаются). Диспетчер ведёт две заявки одновременно: одну играющую
и одну вставленную и ждущую старта; подтверждения уходят строго по порядку.
Команды пульта забирает `src/controls.js`: `GET /commands` → `POST /commands/done` (до исполнения) → действие в PulseSync.

## Состояние плеера для виджета

`getPlayerSnapshot()` → `POST /plugins/music/api/nowplaying` `{trackId, title, artists[], cover, durationMs, positionMs, playing}`.
Шлётся при смене трека, паузе, перемотке (расхождение с ожидаемой позицией > 2,5 с) и раз в 5 с. Виджет сам доигрывает
полосу прогресса между опросами. После сбоя повтор не чаще раза в 5 с.

## Инварианты

- Трек вставляется и заявка берётся у OC только при загруженном текущем треке (`player.canInsert()`): без контекста воспроизведения вставка роняет интерфейс Яндекс Музыки.
- Активна одна заявка; следующая берётся только после подтверждения предыдущей.
- Подтверждение, которое не ушло, хранится в памяти и повторяется; пока оно не ушло, новая заявка не берётся.
- Адрес OC — только loopback по http.
- Идентификаторы из заявки проверяются заново (`^\d+$`), хотя плагин уже их валидировал.

## Модули

`src/oc-client.js`, `src/dispatcher.js`, `src/player.js` — чистая логика с внедряемыми зависимостями (тесты в `test/`);
`src/main.tsx` подключает их к `api` PulseSync.

## События вместо опроса (0.8.0)

Аддон подписывается на топики `queue` и `commands` плагина music (WebSocket `ws://127.0.0.1:8000/plugins/music/ws`, `src/oc-events.js`).

- Пока канал открыт, OC не опрашивается: событие `queue` будит диспетчер (`dispatcher.hint()` → `GET /next`), событие `commands` — пульт (`GET /commands`, подтверждение `POST /commands/done` до исполнения, как раньше).
- При каждом подключении (и при старте аддона) состояние читается один раз обычными запросами: события, пришедшие без связи, потеряны.
- Диспетчер спрашивает `/next` только по поводу: старт, подключение, событие, либо если канала нет. Ответ «заявок нет» снимает повод до следующего события. Локальные задачи (подтверждение старта, таймаут, повтор неотправленных подтверждений) идут по таймеру, но в OC без нужды не ходят.
- Пока канала нет (WebSocket недоступен в окне Яндекс Музыки, OC не запущен, обрыв), работает прежний опрос: иначе аддон молча перестал бы работать. Переподключение — 1 с, 2 с … 30 с; в логе видно «Канал событий OC подключён: опрос отключён» или «потерян».
- Известное допущение: в публичном SDK PulseSync нет WebSocket API, аддон использует `WebSocket` окна; Origin такого окна `music-application://desktop` OC пропускает. Нужен ли `ws://127.0.0.1:8000` в `allowedUrls`, проверяется вживую.

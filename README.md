# PulseRedeem

Аддон PulseSync: забирает заявки на треки Яндекс Музыки из [Overlay Composer](https://github.com/compico/overlaycomposer)
и ставит трек **следующим** в очередь плеера. Twitch, награды и баллы остаются на стороне OC — аддон про них ничего не знает.

```
зритель → награда Twitch → OC (плагин music, очередь) ⇄ аддон → очередь PulseSync
```

Аддон — тонкий мост: `GET /next` → вставка в очередь → трек стал текущим → `POST /started`;
не получилось → `POST /failed` (награда отменяется, баллы возвращаются зрителю).

## Как проверить

1. В OC установите wasm-плагин [`music`](https://github.com/compico/oc-plugins/releases) (инструкция — в его README):
   выдайте разрешения, выберите награду.
2. Установите аддон в PulseSync (`npm run build:sync` или `npm run dev`, см. ниже).
3. Оставьте OC запущенным на `http://127.0.0.1:8000` (порт по умолчанию).
4. Погасите награду со ссылкой на трек (`https://music.yandex.ru/album/…/track/…`).
5. Аддон опрашивает OC раз в 3 секунды. Трек встаёт следующим; когда он становится текущим, награда выполняется.
   Кнопка **Статус заявок** в панели плеера показывает состояние связи.

## Как это работает

- **FIFO.** Вставляется одна заявка за раз. Следующая берётся у OC только после того, как предыдущая стала текущим треком
  (индекс очереди сдвинулся, и на нём лежит ожидаемый `trackId`). Подтверждение старта — по снимку очереди.
- **Подтверждение не теряется.** Если OC недоступен в момент подтверждения, оно повторяется, а новая заявка не берётся
  (иначе OC отдал бы ту же с `resend`, и трек вставился бы дважды).
- **Отказ.** Ошибка вставки или негодная заявка → `/failed`. Трек, не начавший играть за 30 минут → `/failed`.
- **Перезапуск аддона** посреди ожидания: OC повторно отдаст неподтверждённую заявку, трек вставится ещё раз.
- Ответы OC на `400/404/409` не повторяются (OC такое подтверждение уже не примет), остальные ошибки — повторяются.
- Адрес OC — только `http://127.0.0.1:8000` (так же прописан в `allowedUrls` в `addon.config.mjs`).
  Если OC слушает другой порт — поправьте `allowedUrls` и `DEFAULT_BASE_URL` в `src/oc-client.js`.

## Структура

| Файл | Назначение |
|---|---|
| `src/oc-client.js` | HTTP-клиент маршрутов плагина `music`, классификация ошибок |
| `src/dispatcher.js` | автомат «взять → вставить → дождаться старта → подтвердить» |
| `src/player.js` | адаптер над `api.client` PulseSync |
| `src/main.tsx` | подключение к PulseSync: опрос, уведомления, кнопка статуса |

Логика (`oc-client`, `dispatcher`, `player`) не зависит от SDK и проверяется обычным `npm test`.

## Сборка

Требуется Node.js 22.12+.

```bash
npm install
npm test
npm run dev          # сборка в каталог PulseSync + слежение
```

После сборки перезапустите PulseSync или обновите интерфейс через Ctrl+R.

## Не проверено

- Работа в живом PulseSync: формат `allowedUrls` для `http://` и доступ к loopback из `api.net.fetch`.
- Поведение очереди при включённых shuffle/repeat: подтверждение старта опирается на сдвиг `currentIndex`.
- Что `POST` из аддона проходит защиту OC от кросс-оригинальных запросов: она пропускает запросы без заголовка `Origin`,
  что ожидаемо для `api.net.fetch` из основного процесса. Если аддон шлёт `Origin`, OC ответит `403`, и это будет видно в уведомлении.
- Весь путь от Twitch до очереди плеера целиком.
